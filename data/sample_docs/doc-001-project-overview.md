# AgentTrace 项目总览

## 这个项目是什么

AgentTrace 是一个用于**记录、回放、评测和分析 LLM Agent 执行过程**的工具。

一次 Agent 运行结束后，通常只拿到一个最终答案。这个答案无法回答以下问题：

- 这次运行经过了哪些步骤？每步耗时多少？
- 某个节点为什么失败？错误码是什么？
- 工具选对了吗？参数传对了吗？
- 换个 Prompt 版本，结果会变好还是变差？
- Token 和成本花在哪里了？

AgentTrace 的目标就是把运行的**过程**变成可查询、可回放、可度量的数据。

## 项目性质

**本项目为个人独立开发项目。**

- 不使用任何公司代码、公司数据、公司接口或未公开业务信息；
- 所有演示数据均为项目自建的公开/合成数据；
- 项目内所有指标均来自**离线评测**或**样例运行**，不代表任何线上流量、
  生产环境表现、用户量、客户数或商业收益。

## 技术栈

| 层面 | 选型 | 说明 |
|---|---|---|
| 语言 | Python 3.12 | 使用 `StrEnum`、`datetime.UTC` 等 3.11+ 特性 |
| Web | FastAPI | 自带 OpenAPI 文档，便于验收时逐条核对契约 |
| Agent 编排 | LangGraph | 状态图显式表达节点与条件边 |
| 数据校验 | Pydantic v2 | 工具参数、配置、API 请求/响应统一模型 |
| 数据库 | PostgreSQL 16 | 本地测试可退化为 SQLite |
| ORM | SQLAlchemy 2.x | 明确选择 2.x 风格而非 SQLModel，见 doc-005 |
| 缓存 | Redis 7 | 只存短期任务状态，不缓存最终答案 |
| 容器 | Docker Compose | api + postgres + redis 三服务 |
| 测试 | pytest | 默认不依赖网络与外部服务 |

## 核心概念

### Run（运行）

一次 Agent 执行的完整记录。`run` 表保存问题、状态、版本维度与汇总数值。

### TraceEvent（Trace 事件）

运行过程中的一次可观测事件。固定 6 类：`run`、`node`、`tool_call`、
`model_call`、`error`、`final_result`。详见 doc-002。

### sequence（序号）

同一 run 内单调递增的整数，用于保证回放顺序稳定。详见 doc-002。

### degraded（降级完成）

流程跑完了，但证据不足或校验有非致命问题。**不视为成功**，也不计入错误率。

## 边界与限制

1. 不接入任何真实用户数据；
2. 不提供多租户与鉴权，面向本地开发与演示；
3. 不作为生产部署方案（无 TLS、无鉴权、凭据为默认值）；
4. 评测集规模刻意保持小（12 个 case），便于逐条人工核对；
5. 成本估算基于静态价目表，仅用于量级比较。
